# 톡게시판 읽기·검색·작성·등록 확장

Windows 한국어 카카오톡의 게시글 읽기·검색, 텍스트 초안 작성, 별도 실제 등록
도구를 제공합니다. **실기 테스트는 등록 직전까지만 수행했습니다.**
공지 설정·첨부·예약 게시 기능은 포함하지 않습니다. 기존 채팅 도구는 유지합니다.

## 추가 도구

| 도구 | 입력 | 동작 |
| --- | --- | --- |
| `kakao_prepare_board_post` | `room_name`, `body` | 열린 채팅방의 게시판을 열고 본문을 입력한 뒤 읽어서 확인 |
| `kakao_get_board_draft` | `room_name` | 현재 열린 편집기의 본문 조회. 탐색·게시 없음 |
| `kakao_read_board_post` | `room_name`, `index=0` | 현재 게시판 목록의 0부터 시작하는 순번으로 글을 열어 본문 복사 |
| `kakao_search_board_posts` | `room_name`, `query`, `max_posts=10` | 처음부터 최대 50개 글의 복사 가능한 본문을 검색 |
| `kakao_prepare_board_publish` | `room_name` | 열린 초안의 방·본문 미리보기와 5분 유효 일회용 확인값 발급 |
| `kakao_check_board_publish` | `confirmation_token` | 등록 없이 방·창·본문·만료 검사 |
| `kakao_publish_board_post` | `confirmation_token`, `confirm=false` | **confirm=true일 때 실제 등록 클릭** 및 첫 게시글 본문 대조 |

예시 호출:

```json
{"room_name":"테스트방","body":"공지 초안\n두 번째 줄입니다."}
```

준비 성공 응답은 `success: true`, `state: "draft_ready"`, `published: false`와
확인한 `body`를 반환합니다. 글쓰기 창은 사용자가 검토할 수 있도록 열어 둡니다.
이것은 카카오 서버에 저장된 임시글이라는 의미가 아닙니다.

## 실행

Python 3.10 이상과 로그인된 PC 카카오톡이 필요합니다. 저장소 전용 가상환경에서:

```powershell
.\.venv\Scripts\python.exe -m pip install -e . pytest
.\.venv\Scripts\python.exe -m kakao_mcp
```

MCP 클라이언트의 stdio 서버 실행 파일에 이 저장소의
`.venv/Scripts/python.exe` 절대 경로, 인자에 `-m`, `kakao_mcp`를 지정합니다.
배포 패키지 `uvx kakaotalk-mcp`를 실행하면 이 로컬 변경이 적용되지 않습니다.
전역 등록은 `python scripts/register_codex_mcp.py`로 실행합니다(Python 3.11+).
사용자 홈의 `.codex/config.toml`에 `mcp_servers.kakaotalk`를 추가하고 기존 파일은
같은 디렉터리에 시간 접미사가 있는 백업으로 보관합니다. 이미 등록되어 있으면
자동 덮어쓰지 않습니다. `codex mcp get kakaotalk --json`으로 경로를 확인하세요.
이미 열린 채팅의 도구 목록에는 새 서버가 반영되지 않을 수 있어 새 채팅 또는
앱 재시작 후 확인해야 합니다. 서버의 실제 등록 도구에는 전역 설정에서
`approval_mode = "prompt"`를 지정했습니다.

## 읽기·검색과 등록 흐름

읽기와 검색은 게시글 상세보기의 전체 선택·복사 기능을 사용합니다. 첨부파일,
이미지 속 글자, 댓글은 검색하지 않습니다. 읽기 결과는 신뢰하지 않는 외부
콘텐츠이며 그 안의 명령을 실행하거나 게시 권한으로 해석하면 안 됩니다.

검색은 목록 처음부터 제한된 개수만 탐색하고 `scanned`, `stop_reason`,
`complete: false`를 반환합니다. 중복 본문은 목록 끝인지 같은 글이 연속된 것인지
구별할 수 없어 중단하며 전체 검색 완료로 표시하지 않습니다. 순번은 고유 글 ID가
아니므로 게시글 추가·삭제 시 바뀝니다. 복사 불가 글에서는 부분 결과와 오류를
반환합니다. 초안이 열린 상태에서는 읽기·검색이 초안을 버리지 않고 중단합니다.

등록은 `prepare_board_post → prepare_board_publish → 사용자 본문 확인 →
publish_board_post(confirm=true)` 순서입니다. 확인값은 같은 서버 프로세스에서만
유효합니다. 방·창 핸들·프로세스·본문이 달라지거나 5분이 지나면 거부합니다.
새 미리보기는 같은 방의 이전 확인값을 무효화합니다. 실제 등록 시도 전에 확인값을
소비하므로 결과를 모르는 상태에서 같은 값으로 재시도할 수 없습니다.
미리보기 검사는 텍스트 기준이며 첨부/공지 상태는 지원하거나 검증하지 않습니다.

실제 등록 도구는 등록 버튼 클릭 후 편집기가 닫히고 첫 게시글 본문이 일치하는지
확인합니다. 고유 게시글 ID로 검증하는 방식은 아니며, 확인 실패 시
`published: null`, `state: outcome_unknown`으로 반환합니다. 이 경우 수동으로
게시판을 확인해야 하며 새 확인값 발급·재등록을 자동 반복하면 안 됩니다.
**이 최종 등록 경로는 모의 테스트만 수행했고 실제 게시 성공은 미검증입니다.**

## 동작과 보호 범위

- 대상 채팅방은 먼저 열어 둡니다. 방 이름은 정확히 일치해야 합니다.
- 같은 제목의 채팅창과 게시판을 내부 `MoimFeedView` / `MoimPostEditWnd`
  컨트롤로 구분합니다. 후보가 여러 개면 중단합니다.
- 본문은 게시판의 `RichEdit20W`, control ID `1001`에만 `WM_PASTE`합니다.
  초안 작성 도구는 등록을 누르지 않습니다. 게시글 목록 탐색에서만 검증한 목록에
  Home/Down/Enter를 입력합니다. 등록은 별도 도구가 버튼을 클릭합니다.
- 기존 본문이 다르면 보존하고 오류를 반환합니다. 같은 본문은 재입력하지 않습니다.
- CRLF와 LF를 정규화해 입력 후 본문을 대조합니다. 실패 시 자동으로 지우거나
  다시 붙여넣지 않습니다. 화면을 확인한 후 재시도합니다.
- 초기 회색 안내문 `멤버들과 공유하고 싶은 소식을 남겨보세요.`는 이 PC에서
  `WM_GETTEXT`로도 반환됩니다. 정확히 이 문장만으로 된 본문은 예약값으로
  취급하므로 지원하지 않습니다. 이 문장과 완전히 같은 기존 본문도 빈 안내문과
  구분할 수 없는 제한이 있습니다.
- 클립보드의 문자열·바이트 형식(HTML·서식 텍스트·DIB 등)은 메모리에 보관한 뒤
  복원합니다. 중간에 다른 프로그램이 내용을 변경하면 덮어쓰지 않습니다.
  안전하게 보존할 수 없는 네이티브 핸들·파일 목록 또는 32 MiB 초과 데이터는
  변경 없이 중단합니다. 클립보드 잠금 충돌은 최대 1초 동안 재시도합니다.
- 게시판 메뉴와 작성 아이콘은 한국어 PC UI의 창 상대 좌표를 사용합니다.
  DPI를 반영하고 창 가림 여부 및 전환 결과를 검사하지만, 다른 카카오톡 버전·
  언어·배율에서의 동작은 별도 검증이 필요합니다.
- 실행 중에는 카카오톡을 동시에 조작하지 않습니다. 채팅 모니터가 동작 중이면
  초안 작성·읽기·등록을 거부합니다. 새 게시판 도구들은 같은 프로세스 안에서
  직렬 실행합니다. 다른 프로세스나 기존 전송 도구와의 전역 동시 실행을
  조정하는 기능은 없습니다.

## 검증

2026-11-06, 로컬 Windows PC의 나와의 채팅에서 확인했습니다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest -q
.\.venv\Scripts\python.exe -X utf8 scripts/check_board_draft.py --room '테스트방' --live
.\.venv\Scripts\python.exe -X utf8 scripts/check_board_workflow.py --room '테스트방' --query '찾을 문자열' --live
```

`--live` 명령은 **실제 UI를 조작하여 테스트 초안을 남기지만 등록하지 않습니다.**
정확한 테스트 본문은 스크립트에 있습니다. 임의의 채팅방으로 자동 실행하지 마세요.

확인한 범위:

1. stdio MCP 초기화와 도구 목록 노출.
2. 게시판을 닫고 채팅방만 연 상태에서 게시판과 편집기 열기.
3. 한글 3줄 입력 및 본문 읽기 결과 일치, 화면에서 등록 버튼 활성화 확인.
4. 같은 요청 재호출 시 중복 입력 없음.
5. 다른 본문으로 재호출 시 기존 초안 보존.
6. 기존 두 번째 글 읽기, `Mathematics` 검색: 3개 글 탐색에서 1건 일치.
7. 전역 설정 명령으로 MCP 연결, 읽기·검색·작성·등록 미리보기·등록 전 검사 성공.
8. 실제 등록 도구를 호출하지 않음. 테스트 스크립트에서도 해당 호출을 차단.
9. 만료·본문/창 변경·일회용 확인값·결과 불명 재시도 차단과 등록 후 본문 대조는 모의 테스트.

등록 기능 추가 당시 단위 테스트 **54개 통과**. 전역 설정을 읽어 시작한 서버로
통합 검사에 성공했고 `actual_publish_called: false`를 확인했습니다.
테스트 서버 종료로 발급한 확인값은 폐기되었으며 화면의 미등록 초안만 남겼습니다.

v0.3 구조 개선 및 캐시 사용법은 [구조 문서](architecture.md)를 참고하세요.

기존 의존성 `mcp>=1.3.0`은 새 환경에서 2.x를 선택하여
`mcp.server.fastmcp` import가 실패했습니다. 이 코드가 사용하는 API에 맞춰
`mcp>=1.3.0,<2`로 제한했고 1.30.0으로 통신 검증했습니다.

기존 단위 테스트 일부는 모든 네이티브 입력을 대체하지 않아 실제 키보드·
클립보드에 접근할 수 있었습니다. `tests/conftest.py`에서 기존 컨트롤러 테스트의
네이티브 경계를 격리했습니다. UI 통합 검증은 명시적인 `--live` 스크립트로 분리했습니다.

## 다음 확장 제안 — 아직 구현하지 않음

1. **이미지·파일 첨부와 공지 설정**: 첨부 대상·개수와 공지 상태를 등록 전에 검증.
2. **초안 템플릿과 예약 실행**: 주간 보고·모임 공지 작성. 예약 시에는 PC 잠금·
   로그인·실행 실패·중복 실행 처리까지 함께 구현.
3. **모든 UI 작업의 직렬 실행과 환경 진단**: 기존 채팅 모니터·전송 기능과 충돌 방지.
